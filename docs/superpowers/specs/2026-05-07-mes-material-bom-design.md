# MES 物料管理与 BOM 维护设计

## 目标

补齐一个可用的基础版 MES 物料管理模块，以及一个以产品为主线的 BOM 维护流程。用户应当可以先独立维护物料主数据，再从产品管理进入 BOM 维护，为某个产品配置所需物料及用量。

## 当前项目现状

- 前端已经有一个完成度较高的产品管理页面，位于 `frontend/src/pages/MESManage/product/index.tsx`。
- 前端菜单里已经预留了 `物料管理` 和 `BOM管理`，但 `frontend/src/pages/MESManage/material/index.tsx` 目前是空文件，也还没有真正可用的 BOM 页面。
- 后端已经存在 `Material`、`Bom` 的实体、DTO、Mapper、Service、Controller 以及初始化测试数据。
- 当前 BOM 后端返回的数据仍然偏底层，只包含 `materialId` 这类关联字段，不足以直接支撑前端页面展示，因为页面还需要展示物料名称、编码、类型、单位等信息。

## 面向用户的功能设计

### 1. 物料管理

`生产管理 > 物料管理` 作为一个独立的主数据页面存在。

页面支持：

- 分页列表
- 按物料名称或编码搜索
- 按物料类型筛选
- 新增物料
- 编辑物料
- 删除物料
- 展示启用/禁用状态

交互风格尽量复用当前产品管理页面，保证 MES 区域使用体验一致。

### 2. 以产品为主线的 BOM 维护

`生产管理 > 产品管理` 保留当前产品 CRUD 能力，并在每一行增加一个 `BOM维护` 操作按钮。

用户点击 `BOM维护` 后，进入该产品专属的 BOM 详情维护页，而不是把 BOM 直接塞进产品编辑弹窗里。这个做法更符合基础 MES 的常见模式：

- 产品是主记录
- BOM 是产品的从属明细
- 物料是被 BOM 引用的主数据

### 3. BOM 详情页

BOM 页面包含：

- 顶部显示当前产品的摘要信息：产品名称、产品编码、规格、状态
- 下方显示该产品的 BOM 明细表
- 支持新增 BOM 明细、修改用量、删除明细

新增 BOM 明细时：

- 产品由页面上下文固定，不允许在表单里修改
- 物料必须从现有物料中选择
- 只允许选择启用中的物料
- 用量必须大于 0

这套交互比较符合轻量级 MES 对 BOM 维护的基础做法。

## 数据与接口设计

### 物料接口

复用现有后端接口：

- `GET /api/material/list`
- `GET /api/material/{id}`
- `POST /api/material`
- `PUT /api/material/{id}`
- `DELETE /api/material/{id}`

前端新增 `materialApi`，接口封装形式与当前 `productApi` 保持一致。

### BOM 接口

复用现有后端接口作为基础：

- `GET /api/bom/list?productId=...`
- `GET /api/bom/{id}`
- `POST /api/bom`
- `PUT /api/bom/{id}`
- `DELETE /api/bom/{id}`

为了让前端可直接渲染 BOM 明细表，后端应当把 BOM 列表返回改造成“可展示的数据结构”，而不是仅返回关系表字段。建议增加独立的响应对象，例如 `BomVO`。

建议的 BOM 列表项字段：

- `id`
- `productId`
- `materialId`
- `materialName`
- `materialCode`
- `materialType`
- `unit`
- `quantity`

## 后端设计

### 物料模块

当前后端物料 CRUD 已经存在，因此后端在物料模块上的改动应尽量小：

- 校验现有字段校验是否满足前端表单需要
- 保留名称/编码关键字搜索
- 保留类型筛选
- 继续复用现有分页响应结构

### BOM 模块

当前 BOM 后端更像“关系表 CRUD”，需要提升为能直接支撑页面展示的能力。

建议改动：

- 新增 `BomVO` 或等价响应对象
- 查询某产品 BOM 列表时，联表查询物料信息
- 创建 BOM 时校验 `productId` 是否存在
- 创建/更新 BOM 时校验 `materialId` 是否存在
- 校验 `quantity > 0`
- 限制同一产品下不能重复添加同一物料

这些能力足够支撑基础 MES，不需要在本次实现里扩展 BOM 版本、替代料、有效期等复杂能力。

### 物料管理页结构

整体交互复用当前产品管理页的模式：顶部搜索与操作区 + 表格 + 弹窗表单。

字段建议包括：

- 物料名称
- 物料编码
- 物料类型
- 库存数量
- 单位
- 状态

### BOM 页面结构

BOM 页面建议包含：

- 返回产品管理页的返回入口或面包屑
- 产品摘要卡片
- BOM 明细表
- 新增/编辑弹窗

表格字段建议包括：

- 物料名称
- 物料编码
- 物料类型
- 单位
- 用量
- 创建时间

表单字段建议包括：

- 物料选择
- 用量

由于页面已经固定在某个产品上下文里，表单中不再允许修改产品本身。

## 异常与边界处理

- 同一产品下重复添加相同物料时，后端返回清晰错误信息，前端直接提示
- 用量非法时，前端先做表单校验，再由后端兜底校验
- 产品或物料不存在时，后端返回明确错误
- 某产品暂时没有 BOM 明细时，前端展示正常空状态，而不是报错
