# MES 工序管理与工艺路线管理设计

## 目标

补齐一个可用的基础版 MES 工序管理模块，以及一个可维护“路线主表 + 工序顺序明细”的工艺路线管理模块。用户应当可以先维护工序主数据，再在工艺路线中配置工序组成与执行顺序。

## 当前项目现状

- 前端已经完成了产品管理、物料管理以及产品下钻式 BOM 维护。
- 前端菜单中已经预留了 `工序管理` 和 `工艺路线管理` 入口，但当前没有真正可用的页面。
- 后端已经存在 `MesProcess`、`Route`、`RouteProcess` 的实体、DTO、Mapper、Service、Controller，以及初始化测试数据。
- `Process` 模块后端 CRUD 已经基本完整，可直接支撑前端页面。
- `Route` 模块后端虽然已经支持主表 CRUD 和写入 `route_process` 关联表，但 `getRouteWithProcesses()` 目前没有真正把工序明细组装返回给前端，因此还不具备完整的维护能力。

## 面向用户的功能设计

### 1. 工序管理

`生产管理 > 工序管理` 作为独立主数据页面存在。

页面支持：

- 分页列表
- 按工序名称或编码搜索
- 新增工序
- 编辑工序
- 删除工序
- 展示启用/禁用状态

页面风格复用现有产品管理、物料管理的交互模式，保持 MES 区域体验一致。

### 2. 工艺路线管理

`生产管理 > 工艺路线管理` 采用“路线主表 + 工序明细维护”的方式实现。

路线主表负责维护：

- 路线名称
- 路线编码
- 路线描述
- 路线状态

每条路线增加一个 `维护工序` 操作按钮，用于维护该路线下的工序清单与执行顺序。

### 3. 工艺路线的工序明细维护

点击 `维护工序` 后，打开工序维护弹窗或详情弹窗，展示该路线当前绑定的工序列表。

用户可执行：

- 新增工序到路线
- 删除路线中的工序
- 设置工序执行顺序 `sequence`

基础版 MES 下，路线的核心就是“由哪些工序组成”以及“这些工序按什么顺序执行”，因此本次不扩展更复杂的工艺参数配置。

## 数据与接口设计

### 工序接口

复用现有后端接口：

- `GET /api/process/list`
- `GET /api/process/{id}`
- `POST /api/process`
- `PUT /api/process/{id}`
- `DELETE /api/process/{id}`

前端新增 `processApi`，封装形式与当前 `productApi`、`materialApi` 保持一致。

### 工艺路线接口

现有后端接口：

- `GET /api/route/list`
- `GET /api/route/{id}`
- `GET /api/route/{id}/with-processes`
- `POST /api/route`
- `PUT /api/route/{id}`
- `DELETE /api/route/{id}`

本次重点补强 `GET /api/route/{id}/with-processes`，让它真正返回可供前端渲染和编辑的工序明细，而不是只返回路线主表。

建议新增展示型返回结构，例如 `RouteVO`：

- `id`
- `name`
- `code`
- `description`
- `status`
- `createdAt`
- `updatedAt`
- `processes`

其中 `processes` 每一项建议包含：

- `processId`
- `processName`
- `processCode`
- `sequence`

## 后端设计

### 工序模块

后端工序 CRUD 已经存在，因此改动应尽量小：

- 复用现有列表分页结构
- 保留名称/编码关键字搜索
- 保留工序编码唯一性校验

### 工艺路线模块

当前工艺路线模块需要从“主表 CRUD + 关联表写入”提升为“可完整读取和维护路线工序明细”的能力。

建议改动：

- 新增 `RouteVO` 或等价的展示型响应对象
- 新增 `RouteProcessVO` 或在 `RouteVO` 内嵌明细结构
- 在查询路线详情时，联表查询 `route_process` 与 `mes_process`
- 返回工序名称、编码和顺序信息
- 创建/更新路线时校验：
  - 工序必须存在
  - `sequence` 必须大于 0
  - 同一路线内不能重复引用同一工序

本次不扩展工序参数、工时、设备约束等复杂工艺能力。

### 工序管理页结构

整体复用现有产品管理页模式：顶部搜索与操作区 + 表格 + 弹窗表单。

字段包括：

- 工序名称
- 工序编码
- 工序描述
- 状态

### 工艺路线管理页结构

页面主体为路线列表，字段包括：

- 路线名称
- 路线编码
- 路线描述
- 状态
- 创建时间
- 操作

操作至少包括：

- 编辑
- 删除
- 维护工序

### 路线工序维护交互

推荐采用“路线列表页 + 工序维护弹窗”的实现方式，而不是单独做详情页。

弹窗中展示当前路线信息摘要和工序明细表。

表格字段建议包括：

- 顺序
- 工序名称
- 工序编码
- 操作

交互建议：

- 顶部按钮支持新增工序行
- 工序通过下拉框从现有工序主数据中选择
- 顺序通过数字输入框维护
- 删除当前工序行

这样实现复杂度较低，也符合基础 MES 管理页的一般交互习惯。

## 异常与边界处理

- 同一路线中重复添加同一工序时，后端返回清晰错误信息，前端直接提示
- 顺序值非法时，前端先做表单校验，后端再兜底校验
- 工序不存在时，后端返回明确错误
- 某条路线还没有配置工序时，明细弹窗展示正常空状态，而不是报错
